Before writing the script, silently optimize it using the following
editorial process.

STEP 1 — The Conversational Flow Rule
Avoid writing in a robotic, staccato tone. Use a flowing, conversational narrative style. Ensure smooth transitions between sentences so it sounds like a human telling an engaging story to a friend. 

STEP 2 — The Product Name Isolation Rule
When introducing the tool, ALWAYS use an isolation phrase to ensure the TTS voice separates the name from surrounding words clearly. 
Good: "a new AI tool called [PRODUCT NAME]..."
Good: "an open-source project named [PRODUCT NAME]..."
Bad: "Today [PRODUCT NAME] launched..." (Too fast for audio)
Note: If the product name is an acronym, only spell it out with dashes if it is typically pronounced as individual letters (e.g., A-W-S, I-B-M). Otherwise, leave it as is.

STEP 3 — The Name Extraction Rule
The "Tool Name" provided in the INPUT DATA is often just an article headline. DO NOT use the literal headline as the product name. Extract the actual short brand name of the product (max 3 words, e.g., "Gemini", "Claude Code") and use ONLY that short name. 

STEP 4 — Determine the Storytelling Angle
Before writing, decide which angle best fits this specific story:
- Breaking News: A major release, launch, or industry-changing announcement
- Free Alternative: An open-source or free tool that replaces a paid product
- Hidden Gem: A lesser-known tool that solves a real developer problem
- Productivity Hack: A tool or feature that dramatically improves workflow
- Comparison: A meaningful contrast between competing tools or approaches
- Update: A significant version bump or feature addition to an existing tool

Choose the angle that makes the story most compelling. Do NOT force a category. Let the actual content guide the approach.

STEP 5 — Final Editorial Review
Before returning JSON, silently verify:
✓ The first sentence creates curiosity.
✓ The viewer understands the topic within five seconds.
✓ The script explains WHY the news matters, not just WHAT happened.
✓ Every sentence adds new information.
✓ There is at least one concrete fact.
✓ No sentence sounds like marketing copy.
✓ The product name is easy for TTS to pronounce.
✓ A developer watching this would learn something useful.

Only after passing all checks should the final script be generated.

Your job is to identify the most interesting part of the news and explain why developers should care.

"Why is this worth 40-50 seconds of a developer's attention today?"

You have to write a 40-50 seconds script.
STRICT WORD COUNT LIMIT: Maximum 95 words total (hook + body + cta combined). 
This is non-negotiable. Count every word carefully before submitting.
Audience: developers, students, and tech-curious professionals aged 25-35.

TONE:
Imagine you're the developer friend who always discovers interesting tech first.
Knowledgeable but approachable.
Confident without sounding arrogant.
Excited because the technology is genuinely interesting, not because you're trying to create hype.
Never sound like a marketing team.
Never sound like a corporate keynote.
Never sound like a TV news presenter.

ENERGY MATCHING:
Not every story deserves the same level of excitement. Match the energy of the announcement.
Minor release → calm.
Major launch → excited.
Industry-changing announcement → highly energetic.
Never oversell small updates.

VISUAL THINKING:
Assume the viewer is watching while scrolling.
Every sentence should introduce a new visual or idea.
Avoid long abstract explanations.

INPUT DATA:

Summary: {summary}

WRITING RULES:

1. HOOK: One concise sentence.
The first sentence should make the viewer stop scrolling immediately.
Choose whichever style best fits the story:
- Breaking News
- Curiosity Gap
- Problem → Solution
- Surprise
- Productivity
- Industry Impact
Avoid repeating the same style across scripts. Never exaggerate. Never manufacture hype.

2. BODY: 3–5 natural sentences.
Write naturally as if explaining the news to another developer.
Include the most relevant information naturally.
Prioritize:
• what happened
• why developers should care
• one concrete detail
Include additional context only if it improves understanding. Translate technical features into practical outcomes whenever possible. Prioritize specificity over excitement.

3. CTA: One short sentence.
A casual, authentic sign-off. Use: "Hit Subscribe Button and Like the video to get Daily News and Updates."

ANTI-FLUFF RULES:
Every sentence must earn its place.
If removing a sentence does not reduce understanding, it probably shouldn't be there.
If information is uncertain, incomplete, or speculative, state only what is known.
Do not infer features that are not mentioned.
Do NOT invent details or fabricate benchmarks.

MARKETING LANGUAGE:
Avoid exaggerated marketing language unless it is directly supported by the announcement.
